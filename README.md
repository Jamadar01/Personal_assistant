# Sara

A read-only assistant over Gmail, Google Calendar and the weather. Ask it what is waiting
on a reply, what your week looks like, or whether it will rain in Pune - it answers by
calling tools, never from memory.

**It cannot write.** The Gmail and Calendar MCP servers expose tools for sending, editing
and deleting, and those are filtered out in `build_agent()` before the model is ever shown
the list. The system prompt says the same thing, but the filter is what enforces it - a
prompt is not a permission system, and email bodies are untrusted input.

## Running it locally

Needs Python 3.14, Node 22, and Google OAuth already authorised on this machine (the
browser flow cannot run inside a container).

```bash
pip install -r requirements.txt
cd web && npm install && npm run build && cd ..
uvicorn server:app --port 8000
```

Then open http://localhost:8000 - FastAPI serves both the API and the built front end.

While working on the front end, run Vite instead so edits reload:

```bash
cd web && npm run dev     # http://localhost:5173, proxies /api to :8000
```

## How it fits together

```
web/          React + TypeScript. Reads an SSE stream, renders tokens as they arrive.
server.py     FastAPI. One turn per POST /api/chat, streamed back as SSE.
main.py       The agent itself: the model, the tool list, and the system prompt.
```

`main.py` knows nothing about HTTP, and `server.py` knows nothing about prompts. The
agent loop - model calls a tool, reads the result, decides what to do next - is built by
`create_agent` and runs to completion inside a single `astream` call.

Conversation history lives in a dict in memory, keyed by conversation id. It is lost when
the process restarts, which for a single-user assistant is an acceptable trade.

## Configuration

| Variable | Required | What it does |
|---|---|---|
| `OPENAI_API_KEY` | yes | Model access |
| `APP_PASSWORD` | on any public host | HTTP Basic password. Unset means no auth |
| `GOOGLE_OAUTH_KEYS` | in containers | Contents of `~/.gmail-mcp/gcp-oauth.keys.json` |
| `GMAIL_CREDENTIALS` | in containers | Contents of `~/.gmail-mcp/credentials.json` |
| `CALENDAR_TOKENS` | in containers | Contents of `~/.config/google-calendar-mcp/tokens.json` |
| `DEBUG_EVENTS` | no | `1` logs tool calls, arguments and timings |

The three credential variables exist because both MCP servers read Google credentials from
fixed paths on disk and cannot take them from the environment. `write_credentials()` writes
them out at startup. Locally they are unset and the real files are already in place.

`DEBUG_EVENTS=1` prints tool arguments, which for this agent means fragments of your mail.
Leave it off anywhere the logs are not private.

## Deploying

Built as a single image: Node builds the front end, Python runs it, and Node stays in the
runtime image because the MCP servers are `npx` subprocesses.

```bash
docker build -t assistant .
docker run -p 10000:10000 -e OPENAI_API_KEY -e APP_PASSWORD=... assistant
```

Deployed on **Render** as a Docker web service, described by `render.yaml`. Create it with
New > Blueprint pointed at this repo, then fill in the five secrets in the dashboard - they
are declared `sync: false`, so Render prompts for them rather than reading them from the
repo. Pushing to the configured branch redeploys.

Run **one replica only**. The conversation dict is process-local, the MCP servers are
stdio children of this specific process, and the turn lock only serializes within it - two
replicas would answer with no memory of each other's turns. Render's free plan is
single-instance, so this is enforced for free until the plan changes.

Things that will bite, in the order they are likely to:

- **512 MB on the free plan.** Python plus two Node subprocesses is close to the limit. An
  OOM here looks like a restart in the middle of a turn, not an error message.
- **Free services spin down after 15 minutes idle** and take about a minute to wake. Every
  wake loses all conversation history. The MCP servers are baked into the image rather than
  fetched by `npx` on demand, so waking does not also pay the package download.
- **`/api/health` returns 200 as soon as uvicorn is listening**, which is before
  `build_agent()` has finished starting the MCP servers. Render will call the service live
  while the first request would still get a 503. Returning 503 until `AGENT is not None`
  would fix both that and the red bubble on first load.
- **Google's OAuth "Testing" mode expires refresh tokens after seven days.** Until the
  OAuth app is published or made Workspace-internal, the deployed instance stops working
  weekly and the credential secrets have to be regenerated by hand.
